# Lesson 1.1 Runtime Skeleton

## 目标

Lesson 1.1 建立 `packages/agent-runtime` 的最小工程骨架，让后续 provider、tool、context、session 和 agent loop 都能在稳定边界内演进。

这一小节不实现业务能力，重点是把目录、类型管理、测试和检查命令放好。

## 当前状态

状态：learning complete in `lesson1-agent-loop-basic-debug`

当前 tag 已经证明：

- runtime package 可以独立 typecheck、test、check。
- `src/types/*.type.ts` 可以承载跨模块 contract。
- 测试目录和 placeholder tests 可以支撑后续小步实现。
- root 保持产品级目录，不把 runtime 文件散落在项目根目录。

## 关键文件

- `packages/agent-runtime/package.json`
- `packages/agent-runtime/tsconfig.json`
- `packages/agent-runtime/vitest.config.ts`
- `packages/agent-runtime/src/types/*.type.ts`
- `packages/agent-runtime/tests/*.test.ts`

## 实现作用

这一小节解决两个问题：

- 让 TypeScript runtime 能脱离 SwiftUI app 做单元测试。
- 让类型、实现、测试从第一天按模块放置，避免后续 agent loop 代码变成混合文件。

## 类型管理

规则：

- 命名类型统一放在 `packages/agent-runtime/src/types/*.type.ts`。
- 实现文件只通过 `import type` 引用跨模块 contract。
- 每个功能小节只补自己需要的类型，不在 1.1 一次性定义所有未来类型。

## 验收标准

- `packages/agent-runtime` package 存在。
- `src/types`、`src/core`、`src/providers`、`src/tools`、`src/context`、`src/session` 等目录存在。
- `bun run typecheck` 通过。
- `bun run test` 通过。
- `bun run check` 通过。

## 暂不做

- 不定义完整 agent loop 类型。
- 不接真实 provider。
- 不实现 tool registry。
- 不实现 session persistence。
