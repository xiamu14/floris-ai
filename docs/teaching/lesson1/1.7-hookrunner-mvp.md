# Lesson 1.7 HookRunner MVP

## 目标

Lesson 1.7 实现内部 typed hooks，让 context、tool、stop 和 interrupt 都有稳定 lifecycle extension point。

HookRunner 放在 Lesson 1 后段，是因为前面需要先让 context、session、permission boundary、agent loop 和 stream event 路径稳定。

## 当前状态

当前只有目录和测试占位，没有真实 hook pipeline。

## 第一版 Hooks

- `SessionStart`
- `BeforeContextBuild`
- `AfterContextBuild`
- `PreToolUse`
- `PostToolUse`
- `Stop`
- `UserInterrupt`

## 设计原则

- hook 输入输出必须 typed，类型写入 `hook.type.ts`。
- hook 调用顺序必须稳定。
- hook result 写入 session event 或 stream event。
- `PreToolUse` 可以阻止 tool 执行。
- `Stop` 可以要求继续一轮。
- `UserInterrupt` 只做清理和记录，不应该阻止中断。

## 和 Tool Architecture 的关系

Lesson 1.3 先定义 tool result envelope、output policy 和 hook payload 的方向。Lesson 1.7 再实现 `HookRunner` 调用这些 payload。

Tool optimizer 负责把真实世界输出变成可用信息。Runtime guard 负责决定什么能进入 model context。Hooks 负责在 lifecycle point 观察、阻止、记录或调整决策。

## 验收标准

- hook 调用顺序可断言。
- `PreToolUse` 阻止 tool 后，tool 不执行。
- `Stop` 返回 continue 后，loop 再跑一轮或返回 `stop_blocked` stub。
- `UserInterrupt` hook 被调用，但不会阻止 abort。
- hook event 能进入 session event / stream event。

## 暂不做

- 不做用户脚本。
- 不做 shell hook。
- 不做 HTTP hook。
- 不做 prompt-based hook。
- 不做 agent 自主调用 hook。
