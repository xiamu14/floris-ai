# Lesson 1.6 Stream Rendering Web UI

## 目标

Lesson 1.6 提供本地 stream rendering Web UI，让学习者和开发者可以直接看到 agent run 的用户可见过程。

它不只是把 CLI output 搬到网页，而是验证未来 Floris macOS app 也需要的 stream event contract。

## 当前状态

状态：not implemented

CLI demo 可以继续作为 smoke script，但 Lesson 1.6 的主要交付是 Stream Web UI。

## 用户可见输出

Web UI 应该增量渲染：

- user message。
- assistant text delta。
- final assistant message。
- tool call started / finished。
- tool result summary。
- context build summary。
- stop reason 和 error state。
- MLflow trace id 或 trace link。

## 第一版边界

- 只做本地开发 UI，不做生产 macOS app。
- 使用轻量 HTTP server 提供页面和 `/runs` stream endpoint。
- transport 第一版使用 SSE。
- Web UI 不实现 agent loop，只消费 runtime stream events。
- stream event 不传 secret 原文。
- MLflow trace 继续作为深度观察入口。

## Stream Event Contract

第一版最小事件：

```text
run.started
message.delta
message.completed
tool.started
tool.completed
context.built
run.completed
run.failed
```

## 设计重点

- UI 不能等整个 run 完成后一次性渲染。
- assistant message 要按 delta 追加。
- tool call 先出现 pending 状态，再更新为 success / error。
- final answer 由 message deltas 组成，不只依赖最后 JSON summary。
- trace link 是深度观察入口，不替代用户可读 timeline。

## 为什么从 CLI 改为 Stream Web UI

主流 AI agent 产品的核心体验是 chat / run timeline。用户需要看到 agent 正在输出、调用 tool、拿到结果和继续生成，而不是等 terminal 打印一个完整 JSON。

Stream Web UI 可以更早暴露这些问题：

- partial message 渲染是否顺畅。
- tool pending state 是否清楚。
- stop reason 是否能被用户理解。
- trace link 是否能和一次 run 对上。

## 验收标准

- Web UI server 可以启动。
- stream endpoint 可以输出 `run.started`、`message.delta`、`tool.started`、`tool.completed`、`run.completed`。
- 前端 reducer 可以把 stream events 合成为 assistant message 和 tool timeline。
- scripted provider 下能跑到 `assistant_done`。
- `bun run typecheck` 通过。
- `bun run test` 通过。
- `bun run check` 通过。

## 暂不做

- 不做生产 macOS UI。
- 不做完整 thread sidebar。
- 不做 Context Inspector UI。
- 不做 approval UI。
- 不做复杂多 run 管理。
