# Lesson 1.2 ModelProvider Boundary

## 目标

Lesson 1.2 把 agent loop 和具体 model SDK 分开。`AgentLoop` 只依赖 Floris 内部的 `ModelProvider` contract，不直接依赖 OpenAI SDK、MIMO 或其他平台。

- OpenAI-compatible provider adapter。
- MIMO config 选项。

- provider request / response mapper。

## 数据流

```text
AgentRole
  -> resolveProviderForRole(config, role, { providerType })
  -> modelRef
  -> provider config
  -> createOpenAICompatibleProviderFromEnv()
  -> OpenAICompatibleModelProvider
  -> ModelEvent stream
```

## 设计要点

- `ModelProvider` 使用 Strategy，agent loop 不关心底层 SDK。
- OpenAI-compatible provider 使用 Adapter，把 SDK response 转成 Floris 内部 `ModelEvent`。
- `resolveProviderForRole()` 使用显式 `providerType` 参数选择 provider 创建逻辑，不用 callback 隐藏主流程。
- `createOpenAICompatibleProviderFromEnv()` 从 env 读取 `apiKeyEnvName`，缺 key 返回结构化 `missing_api_key`。
- provider 内部缓存 SDK client，避免一次 run 重复创建 client。
- MIMO 是当前阶段 provider 选项，不是产品默认配置。

## 当前简化

- 只支持 `providerType: "openai-compatible"`。
- Anthropic / local provider 还没有 adapter。
- SecretStore 还没有实现，当前只读 env。
- 当前 OpenAI-compatible provider 使用非 streaming Chat Completions；后续如果接 streaming，delta 拼接应该留在 provider adapter 内。

## 验收标准

- `coder` role 能解析到配置里的 provider 和 model。
- 未配置 role fallback 到 `defaultRole`。
- model 或 provider 缺失时返回可展示的配置错误。
- OpenAI response 能映射成 `text_delta`、`tool_call_done`、`usage`、`done` 或 `error`。
- API key 不进入 prompt、event payload 或 trace 明文。
- provider test 不直接依赖真实网络。

## 暂不做

- 不做完整多 provider registry。
- 不做 macOS Keychain 接入。
- 不做 provider 自动切换。
- 不把 agent role 直接绑定到具体 SDK。
